# 16. Portal 运营端重设计

状态：第一版已实施，待运营验收  
日期：2026-07-10  
适用范围：refactor-app/frontend、Portal 查询 API、Job/日志查询 API  
替代关系：本文档是 Portal 运营端的唯一目标设计；15-ops-console-ui-design.md 只作为历史记录，不再作为实施依据。

## 1. 目标

Portal 面向日常运营，不是数据库字段浏览器，也不是接口调试工具。

运营进入系统后必须能快速完成四件事：

1. 看出哪里异常、影响多少数据、是否仍在运行。
2. 从账号、空间、凭证、下游渠道任一对象进入完整上下文。
3. 用选择器和业务表单发起操作，不手填已有对象 ID、JSON、Cookie 或内部默认参数。
4. 从 Job 直接看到当前阶段、成功/失败数量、失败原因和上游接口结果。

本次重设计覆盖：

- 信息架构与导航。
- 表格字段、密度、分页、排序、筛选、批量选择。
- 时间、时区、持续时间展示。
- Job、Work、Event 和控制台日志。
- 新建、编辑、详情、确认弹框与抽屉。
- 状态、错误、空状态、加载状态和刷新策略。
- 各页面的运营视图。
- 为新 UI 必须补齐的后端查询能力。

本次不改变账号、空间、成员、凭证、推送、回收的业务模型，不改变 Job/Work 执行机制，不新增业务表。

## 2. 现状证据

### 2.1 当前数据规模

2026-07-10 本地数据库实际数量：

| 数据 | 数量 |
| --- | ---: |
| jobs | 1,806 |
| work_items | 29,331 |
| job_events | 46,358 |
| user_accounts | 1,336 |
| spaces | 1,259 |
| space_memberships | 894 |
| space_credentials | 327 |
| space_push_bindings | 115 |
| space_push_attempts | 415 |

因此，Portal 不能继续把所有数据一次性返回浏览器后再分页。代理列表仅一次请求就会返回 20,500 行。

### 2.2 当前实现问题

| 问题 | 当前证据 | 运营影响 |
| --- | --- | --- |
| 全量拉取后前端筛选 | DataTable.vue 对 props.rows 使用 JSON.stringify(row) 搜索和前端 slice 分页 | 大数据页面慢，搜索语义不可控，无法知道全库总数 |
| 大多数列表 API 无分页 | user-accounts、spaces、space-credentials、proxies 均直接 all() | 大量无用数据传输和渲染 |
| Jobs 只返回最近 100 条 | GET /jobs?limit=100 | 历史任务无法通过页面查询 |
| 时间原样展示 | 页面直接输出 created_at、updated_at、started_at | UTC/本地时间混淆，无法快速比较耗时 |
| 顶部健康状态是静态文字 | OpsLayout.vue 固定显示数据库正常、接口正常、Worker 手动 | 状态可能与真实运行不一致 |
| 表格每个普通单元格都是复制按钮 | DataTable.vue 普通 cell 使用 button | 点击语义混乱，无法正常选中文字，复制无反馈 |
| 筛选不一致 | 通用表格做前端等值筛选；成员页另有后端筛选 | 同一操作在不同页面行为不同 |
| 操作依赖手填 ID | 代理绑定、邮箱生命周期、Business AT 等要求输入 ID | 容易填错对象，运营无法确认上下文 |
| 高级原始材料直接暴露 | 管理员导入要求粘贴 session JSON、Cookie、浏览器 Headers | 表单噪声大，敏感信息处理不统一 |
| 创建/编辑方式不一致 | 页面大表单、内联编辑、手写 overlay、window.confirm 并存 | 交互不可预测，校验和关闭行为不一致 |
| Job 详情堆四张表和 JSON | JobTraceView 顺序展示 Work、Run、Step、Event、JSON | 无法快速回答现在卡在哪和为什么失败 |
| 日志入口分裂 | Job Trace 和 Automation Monitor 各自处理日志 | 同一 Job 需要跨页面排查 |
| 视觉过度装饰 | 径向渐变、大阴影、16px 圆角、卡片嵌套 | 密集运营数据可读性差 |

## 3. 运营任务模型

Portal 不按数据库表组织操作，而按运营任务组织入口。

~~~mermaid
flowchart LR
  A["发现异常"] --> B["定位业务对象"]
  B --> C["发起修复或重试 Job"]
  C --> D["查看 Job 进度"]
  D --> E{"最终结果"}
  E -->|成功| F["返回对象详情并刷新状态"]
  E -->|失败| G["查看失败 Work 与上游接口"]
  G --> C
~~~

主流程：

~~~text
账号注册 -> Session 可用 -> 加入空间 -> 识别空间 -> 创建空间凭证
空间凭证 -> 下游渠道坑位/余额判断 -> 推送 -> 使用额度 -> 结算/回收
失败 Job -> 失败 Work -> 失败阶段 -> 错误码/接口响应 -> 重试或修复数据
~~~

## 5. 页面骨架与视觉规范

### 5.1 页面骨架

~~~text
┌──────────────┬─────────────────────────────────────────────────────┐
│ 分组导航     │ 顶栏：全局搜索 / 最近任务 / 真实健康状态 / 时区    │
│              ├─────────────────────────────────────────────────────┤
│              │ 页面标题 + 主操作 + 次操作                         │
│              ├─────────────────────────────────────────────────────┤
│              │ 筛选栏（可折叠高级筛选）                           │
│              ├─────────────────────────────────────────────────────┤
│              │ 数据表格 / 运营工作区                              │
│              ├─────────────────────────────────────────────────────┤
│              │ 分页与总数                                         │
└──────────────┴─────────────────────────────────────────────────────┘
                                      右侧：详情/编辑抽屉（按需）
~~~

### 5.2 视觉方向

定位：安静、紧凑、可扫描的运营工作台。

- 使用中性石墨色背景，不使用光斑、渐变球或径向渐变装饰。
- 页面区域采用无阴影分区；卡片只用于指标、重复对象和弹框。
- 卡片和弹框圆角不超过 8px。
- 主色只用于选中、链接和主操作；成功、警告、错误使用独立语义色。
- 表格默认行高 40px，紧凑模式 34px，宽松模式 48px。
- 页面标题 20px；面板标题 14px；表格正文 13px；辅助文字 12px。
- 字间距固定为 0，不使用负字间距。
- 操作按钮使用 Lucide 图标；熟悉操作优先图标按钮并提供 tooltip。
- ID、错误码、请求路径使用等宽字体；业务名称和邮箱使用 UI 字体。
- 不在页面中显示长篇功能说明，帮助内容放 tooltip 或帮助抽屉。

## 6. 全局表格规范

### 6.1 服务端数据协议

所有主列表统一使用服务端分页、筛选和排序：

~~~http
GET /resource?page=1&page_size=50&sort=-updated_at&status=failed&q=email
~~~

统一响应：

~~~json
{
  "items": [],
  "page": 1,
  "page_size": 50,
  "total": 1336,
  "sort": "-updated_at"
}
~~~

规则：

- page_size 支持 20、50、100、200，默认 50，最大 200。
- 排序字段由各接口白名单控制。
- 文本搜索只查询文档明确的字段，不再搜索整个 JSON。
- 所有筛选条件同步到 URL query，刷新和分享 URL 后仍可复现。
- 后端返回 total，页面不能用当前数组长度冒充总数。
- 20,500 条代理、29,331 条 Work、46,358 条 Event 必须服务端分页。

### 6.2 表格结构

每张主表最多默认展示 8 个业务列：

1. 主对象：名称、邮箱或任务类型。
2. 关键归属：空间、账号或渠道。
3. 当前状态。
4. 运营指标：额度、坑位、成功/失败等。
5. 最近异常。
6. 最近更新时间。
7. 行操作。

内部 ID、全部时间、原始字段进入详情抽屉，不在主表横向堆满。

表格交互：

- 表头固定，首列可按页面需要固定。
- 支持列排序、列显隐和密度选择；偏好保存在 localStorage。
- 单击行打开详情抽屉，不直接触发业务动作。
- 只有 ID、邮箱、URL 旁显示复制图标；复制成功显示短暂反馈。
- 长错误信息两行截断，点击展开完整错误，不依赖浏览器 title。
- 空值统一显示“-”，布尔值显示“是/否”或状态图标。
- 状态显示中文，tooltip 保留原始枚举值。
- 行操作默认收在“更多”菜单；最高频且安全的动作保留一个图标按钮。

### 6.3 批量选择

- 表头只选择当前页，不隐式选择全部查询结果。
- 批量操作条固定在表格底部，显示已选条数和涉及对象数。
- 翻页后保留已选 ID，并允许一键清空。
- 不满足动作条件的记录不进入提交集合，提交前显示可执行和忽略数量。
- 危险批量操作必须二次确认并展示影响范围。

## 7. 时间与持续时间规范

### 7.1 时区

- 数据库和 API 继续使用 UTC ISO 8601。
- Portal 默认显示 Asia/Shanghai。
- 顶栏显示“北京时间 UTC+8”。
- 用户可切换北京时间、浏览器本地时间、UTC，选择保存在 localStorage。

### 7.2 展示格式

| 场景 | 格式 |
| --- | --- |
| 当前年份表格 | 07-10 23:21:19 |
| 跨年份表格 | 2025-12-31 23:59:59 |
| 详情/弹框 | 2026-07-10 23:21:19 |
| 次要相对时间 | 3 分钟前 |
| tooltip | 2026-07-10T15:21:19.602Z / UTC |
| 持续时间 | 67.3 秒、6 分 17 秒、1 小时 04 分 |
| 未开始/未结束 | - |

要求：

- 精确时间始终可见；相对时间只能作为辅助。
- Job、Work、Run 必须展示持续时间，运行中动态计算。
- 时间格式化集中在 formatDateTime 工具，页面禁止自行拼接。
- 解析失败显示“时间格式错误”，不能显示 Invalid Date。

## 8. 筛选与搜索规范

### 8.1 筛选栏

默认展示 3 到 5 个最高频条件，其他条件进入高级筛选。

- 查询：提交当前筛选。
- 重置：恢复页面默认查询。
- 已生效条件显示为可移除标签。
- 文本框回车查询；不对每次键入立即发请求。
- 选择状态、类型等离散条件后可以自动查询。
- 显示数据库总数，不能用当前加载数量代替。

### 8.2 搜索语义

| 字段类型 | 行为 |
| --- | --- |
| 邮箱、名称 | 不区分大小写模糊匹配 |
| 内部/外部 ID | 精确匹配；高级选项支持包含 |
| 状态、类型 | 多选枚举 |
| 时间 | 起止时间范围 |
| 错误码 | 精确或前缀匹配 |
| 错误信息 | 模糊匹配 |

禁止继续使用 JSON.stringify(row).includes(q)。

### 8.3 筛选状态

筛选写入 URL。例如：

~~~text
/ops/jobs?status=failed&type=account.protocol_register&from=2026-07-10T00:00:00%2B08:00
~~~

从总览点击指标进入列表时必须携带筛选。

## 9. 状态与错误规范

状态组件维护“业务域 + 原始值”的映射，不能只按字符串全局猜颜色。

~~~text
Job.failed          红色 / 失败
Membership.failed   红色 / 失败
Push.skipped        灰色 / 已跳过
Push.used           绿色 / 已结算使用
Credential.active   绿色 / 可用
Proxy.bound         蓝色 / 已绑定
~~~

主表错误显示：

~~~text
[MAIL_NOT_FOUND] 未找到匹配邮件
~~~

点击后展开：

- 错误码和中文摘要。
- 原始错误信息。
- 发生阶段。
- 上游请求方法、URL、HTTP 状态、x-request-id。
- 首次和最近发生时间。
- 关联 Job、Work、账号、空间。
- 重试、打开对象、复制诊断信息等可执行动作。

API 错误必须解析 FastAPI detail，不能把整段 JSON 字符串直接 toast 给运营。

## 10. 统一 Job 与日志工作台

### 10.1 Job 列表

默认列：

| 列 | 说明 |
| --- | --- |
| 任务 | 中文任务名 + 原始 type 次要展示 |
| 状态 | queued/running/succeeded/failed/cancelled |
| 进度 | 成功、失败、运行、总数 |
| 当前阶段 | 最近一条阶段事件 |
| 最近错误 | error_code + 摘要 |
| 持续时间 | 动态或最终耗时 |
| 发起人 | created_by |
| 开始时间 | 本地格式 |
| 操作 | 查看、取消可取消任务 |

筛选：状态、任务类型、发起人、错误码、时间范围、关键词。

### 10.2 Job 详情

Job 详情改为一个工作台，不再依次堆四张完整表。

~~~text
┌──────────────────────────────────────────────────────────────┐
│ Job 名称 / 状态 / 进度 / 持续时间 / 开始时间 / 操作         │
├───────────────────────────────┬──────────────────────────────┤
│ Work 列表                     │ 当前选中 Work 详情           │
│ 状态/对象/阶段/耗时/错误      │ 输入摘要/输出摘要/错误       │
├───────────────────────────────┴──────────────────────────────┤
│ 事件时间线：时间/级别/阶段/接口/结果                         │
├──────────────────────────────────────────────────────────────┤
│ 选中事件详情：请求摘要 / 响应摘要 / 关联对象                 │
└──────────────────────────────────────────────────────────────┘
~~~

默认行为：

- 失败 Job 自动选择第一个失败 Work 和最后一个 ERROR 事件。
- 运行中 Job 自动选择运行中的 Work并开启自动刷新。
- 成功 Job 展示汇总和最后完成事件，不自动展开原始 JSON。

### 10.3 事件时间线

字段：时间、级别、业务阶段、方法和请求路径、HTTP 状态、简要结果、Work。

筛选：级别、Work ID、业务阶段、HTTP 状态、关键词、只看上游、只看失败。

日志策略：

- 默认隐藏 DEBUG。
- 自动刷新只追加新事件，不重复获取整份事件数组。
- 事件使用 after_id 或 after_ts 游标。
- 自动跟随打开时滚动到底部；用户上滚后暂停。
- 显示“有 N 条新日志”，由用户恢复跟随。
- 单次最多返回 500 条，历史日志向上加载。
- 结构化字段优先展示，原始 data_json 放开发者详情。

### 10.4 敏感信息

前端和日志 API 统一掩码：

~~~text
access_token
refresh_token
session_token
cookie / cookie_header / auth_cookie_header
authorization
admin_key
custom_auth_header_value
password
csrf_token
code / code_verifier
otp
~~~

默认日志 API 不返回完整敏感值；请求体、响应体和“复制诊断信息”都使用掩码后的数据。

## 11. 新建、编辑、详情与确认

### 11.1 容器选择

| 场景 | 容器 |
| --- | --- |
| 简单确认、少于 6 个字段 | Modal |
| 新建/编辑复杂对象 | 右侧 Drawer，宽 560-720px |
| 对象详情、关联数据 | 右侧 Drawer |
| 需要完整上下文的 Job | 独立页面 |
| 超长 JSON/Headers 导入 | Drawer 中的高级导入步骤 |

禁止在列表顶部展开大表单，禁止新建和编辑维护两套表单，禁止 window.confirm，禁止要求运营记忆本系统已有对象 ID。

### 11.2 表单规范

- 新建和编辑复用同一个 Form Schema 和组件。
- 字段按基础信息、认证、规则、高级设置分组。
- 只显示当前类型需要的字段。
- 字段失焦和提交时校验，错误紧邻字段。
- 保存失败保留表单内容，不关闭抽屉。
- 有未保存变更时关闭必须确认。
- 提交期间防止重复提交。
- 创建 Job 成功后关闭抽屉并进入 Job 详情。
- 普通资源保存成功后关闭抽屉、刷新当前行并保留筛选。

### 11.3 对象选择器

账号、空间、管理员 Session、凭证、渠道、邮箱租约统一使用可搜索 Combobox：

~~~text
显示：空间名称 / 管理员邮箱
次要：external_space_id
提交：space_id
~~~

多行 ID 输入只能放高级批量输入，并实时解析、去重、校验存在性和显示无效项。

### 11.4 密钥字段

- 编辑时显示“已配置”，不返回旧密钥。
- 留空代表不修改。
- 输入新值后可清空本次修改。
- 支持测试连接；测试结果显示在当前表单中。

### 11.5 危险操作确认

危险删除必须先调用后端 impact/dry-run，展示实际影响：

~~~text
删除管理员 Session
管理员：owner@example.com
将删除：1 个管理员 Session、1 个空间、345 条成员、49 条空间凭证
将保留：推送历史、Job/Work/Event
不会调用：远端删除成员接口
~~~

前端不得自行猜测删除范围。

## 12. 页面设计

### 12.1 总览

目标：回答“现在有什么需要处理”。

指标：

- 运行中 Job。
- 排队 Work。
- 最近 24 小时失败 Job。
- Session 异常账号。
- 未授权成员。
- 推送失败和待结算。
- 可用静态代理。
- 下游剩余坑位。

主体区域：

1. 待处理事项：按影响数量排序，跳到带筛选的列表。
2. 最近自动化运行：长期 Job 的状态、耗时、成功/失败。

### 12.9 常驻 Job

每行提供编辑调度、手动执行一次和查看日志。编辑调度会持久化开关、间隔和参数；手动执行使用当前调度参数作为默认值，允许本次覆盖，但不写回调度配置，也不改变 `next_run_at`。调度关闭时仍允许手动执行。

四个常驻项是任务定义，不重复创建；每次定时或手动执行仍创建独立执行 Job，用于记录 Work、事件、状态和日志。下游推送未指定渠道时，继续按启用渠道分别创建执行 Job。

- 所有页面默认显示北京时间。

- Job、Work、Run 显示持续时间。
- 不直接显示带 +00:00 的原始时间字符串。

- 失败 Job 打开后 3 秒内看到失败 Work、失败阶段、错误码和接口状态。

- 日志筛选可复现，自动跟随可暂停。
- 页面和复制内容不泄露 token、Cookie、密码、OTP 或 verifier。

- 危险删除展示后端计算的实际影响范围。
- 创建 Job 后自动进入统一 Job 详情。
- 操作失败保留用户输入并显示字段级或表单级错误。

### 17.5 运营闭环

- 从总览异常跳到带筛选的资源列表。
- 从资源行进入关联 Job。
- 从失败 Job 返回账号、空间、凭证或渠道。
- 修复或重试完成后原页面看到最新状态，不依赖全页刷新。
